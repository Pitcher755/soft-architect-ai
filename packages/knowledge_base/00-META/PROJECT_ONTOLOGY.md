# 📚 Project Ontology and Ubiquitous Language

This document defines the fundamental terms, concepts, and doctrines that **SoftArchitect AI** and the Human Team will use to communicate. Adhering to this ubiquitous language eliminates ambiguity and ensures architectural consistency.

## 🧠 Core Doctrines

### **Zero Lazy Writing**
The strict operational doctrine forbidding the AI from outputting generic placeholders (e.g., `{{VAR}}`, `[Insert here]`), empty tables, or superficial descriptions. The AI is mandated to invent, propose, and detail realistic technical data to ensure high-density documentation.

### **Root vs. Context Routing (The Path Rule)**
The physical directory separation strategy:
- **Context (`context/`):** The directory housing the evolving knowledge base (Phases 1 to 5).
- **Root (`/`):** The project's main directory housing the Master Meta-files (Phase 6: `README.md`, `AGENTS.md`, `RULES.md`, `CONTRIBUTING.md`).

## ⚙️ Meta-System Concepts

### **Master Workflow**
The unbreakable 6-Phase, 24-Step sequential process that transforms a raw idea into a production-ready software architecture.

### **Gate (Quality Gate)**
A mandatory checkpoint at the end of each Phase. The system (and the Human Team) validates the existence, density, and quality of required artifacts before unlocking the next phase.

### **Golden Template**
Master structural blueprints located in `01-TEMPLATES/`. They define the *exact required structure* of a document. The AI uses these as the skeleton, transforming them into dense artifacts.

### **Master Example**
Fully fleshed-out, highly detailed documents located in `MASTER_WORKFLOW_EXAMPLES/`. The RAG (Retrieval-Augmented Generation) engine uses these to teach the AI the expected *density, tone, and depth* for a given document.

### **Tech Pack**
A curated set of rules, optimal folder structures, and architectural patterns for a specific technology (e.g., `python-fastapi`, `flutter-riverpod`). It acts as the technical "source of truth" during Phase 3 (Architecture).

### **RAG Context Window**
The totality of information the AI "knows" about the current project. It is dynamically built by retrieving the generated `.md` files from the `context/` folder, ensuring the AI maintains perfect architectural memory.

## 📐 Engineering Definitions

### **Artifact**
Any tangible file generated by the Master Workflow (Markdown documents, JSON schemas, Mermaid diagrams, or Code).

### **Hardening**
The process of securing the system against vulnerabilities. In SoftArchitect, we apply hardening *Shift-Left*—meaning security is designed during Phase 2 and 3, long before the first line of code is written.

### **Snapshot**
A frozen, immutable state of the project's architecture at a specific point in time (e.g., MVP approved, V1 released).
